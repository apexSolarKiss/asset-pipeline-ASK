# Portable Package Extraction — 2c Marketing Hero (v1)

## Posture

```text
single portability / extractability attempt
re-expresses one proven package instance outside Airtable
hybrid prose walk + YAML package-instance appendix
the YAML appendix is a concrete tool-agnostic package INSTANCE, not a schema and not a reusable package grammar
instantiation plan is conceptual (a second substrate must represent / preserve / support X) — NOT entity design
read-only Airtable preflight; no Airtable mutation
not schema mandate / not validator / not runtime orchestrator / not structured IA model v3
not an all-mode package system — one package, one mode, one slot
self-superseding when a different package, a second real substrate instantiation, or an operational consumer earns its place
```

This artifact pressures the claim the README now makes: that the deliverable is a **portable asset-definition package** — a substrate-independent definition layer — and that Airtable is one substrate, not the deliverable. It tests that claim against the one chain the prototype has proven end to end in-base: the **2c "Spring Refresh" marketing hero**. The standard the artifact answers to is whether the proven package can be re-expressed and understood without Airtable, and what a second substrate would have to be able to do to hold and run it — not whether a tidy file can be written.

## Architectural question

> Does the proven 2c message-hero package survive re-expression as a substrate-independent artifact that (a) carries the full **creative intent → creative discretion → variance → selection → governance** chain and the information kinds, (b) a non-thread reader can understand without Airtable, and (c) names what a *second substrate* would need to instantiate it — and where does the re-expression force Airtable-shaped assumptions into the open?

The deliverable per `README.md` is the portable definition layer above changing tools. That layer has never been pressured against a *proven, governed* instance outside Airtable. This is that pressure, on the strongest available instance.

## Relationship to the prior extraction attempt (explicit non-redo)

[`non-airtable-extraction-attempt-v1.md`](non-airtable-extraction-attempt-v1.md) extracted a **SKU slice** into **JSON Schema** plus a minimal JSON instance, and concluded: *the data shape is portable; the interpretive / procedural layer is not yet portable.* It scoped itself as SKU-only, JSON-Schema-only, and self-superseding when a different slice, shape, or consumption test earned its place.

This artifact is that different leg — deliberately not a redo:

| | extraction-v1 | this artifact |
|---|---|---|
| object | a *type* shape (JSON Schema) | a concrete *package instance* (YAML) |
| slice | SKU-driven (strongest schema evidence) | marketing / message-driven (the proven in-base governed chain) |
| depth | schema + instance | instance + **walk to instantiation-plan depth** |
| audience | claim-discipline (machine-readable vs machine-usable) | **first reader** (evaluator / implementer) |
| YAML vs JSON | JSON / JSON Schema (test machinery register) | **YAML** so the structured form can carry comments, honesty markers, and held-status cues a first reader needs |

extraction-v1 already established that the relational data shape survives. This artifact does not re-prove that. It pressures what extraction-v1 did not: whether a *whole proven package* reads and instantiates without Airtable, and where the package's load-bearing distinctions either survive substrate-independently or turn out to have been quietly carried by Airtable.

## The walk — reading the package without Airtable

The full instance is in the [YAML appendix](#yaml-appendix--the-2c-marketing-hero-package-instance) below. The walk reads it top to bottom as the bounded-generativity topology / creative-discretion doctrine ([`creative-discretion-doctrine-v1.md`](creative-discretion-doctrine-v1.md)).

- **Creative intent (the aim).** "A message-bearing composition with room to carry an offer/headline; a warm daylit refresh feeling; products serve the message rather than being the subject." This is marketing mode: the anchor is the offer/message, not a SKU. The two products (`SKU-HG-TOWEL-001`, `SKU-HG-BATHMAT-001`) are **peripheral** — present, but subordinate to the message. That mode-shape (products peripheral when the message is the fidelity anchor) reads from the instance without any tool.

- **Creative discretion (the aperture grant).** A distinct carrier — *what may vary* (which bath-textile pieces appear and their arrangement; framing/crop; surface; the placement and extent of the copy-overlay negative space), *bounded by* the four constraints, *anchored to* the two references, *owned by* the marketing curator-of-record, *closing at* hero-slot curation. The grammar conclusion from the discretion arc holds in the re-expression: the aperture grant is one carrier; the constraints ("what may not vary") and references ("what anchors it") are separate carriers. They do not collapse into one "creative direction" field.

- **Constraints (what may not vary).** Four bounded rules, each typed by normative force: `BC-WR-PALETTE` (presentation), `BC-WR-LIGHTING` and `BC-WR-MATERIAL` (fidelity), `BC-WR-NEGATIVE` (hard requirement / avoid-list). Scoped at the brand-system layer ("Warm Restraint") and inherited by the packet. The force-typing and the brand→packet inheritance survive extraction.

- **References (visual anchors).** Two typed references — `REF-WR-BRANDSYS-01` (approved directional, brand-system master, shared across all four mode packets) and `REF-WR-PALETTE-01` (supporting input). **Honesty marker:** in this instance both are *records-with-notes only* — imagery was pending; no image bytes are attached. So the high-bandwidth visual anchoring the architecture treats as the structural override was, *for this instance*, carried by the prose `slot_prompt`, not by reference images. The reference carriers are structurally present and correctly typed; they are image-empty here. The package re-expresses faithfully — including that gap.

- **Required output (the obligation).** Prose in this instance: "1 message-hero (offer-ready, copy space); 1 secondary message-support." Two slots: `SLOT-MSG-HG-001-HERO` (role `message_hero`, **accepted**) and `SLOT-MSG-HG-001-SUPPORT` (role `message_support`, **planned / held** — deliberately not generated). The marketing-mode structured composite-anchor (`messages`) remains held; the obligation reads as prose, which is honest about its evidence depth.

- **Variance (the candidate set).** Generation *fills* the aperture; it does not judge. Seven candidates accumulated on the hero slot as a set — six before a prompt remediation, one after. The slot prompt carries composition + aesthetic only; output framing (3:4 portrait) is a separate setting, not prompt text. **Authorship-bearing discretion surfaced upstream here** at prompt-remediation (the first batch drifted — furniture at an odd angle, robe on a hook, obstructed copy field — and the prompt was remediated once), consistent with the campaign-mode finding that authorship can sit upstream of the seam.

- **Selection (closing the aperture).** The curator ranged the full seven-candidate space and selected the post-remediation take as the one that best carries the offer within the envelope — `curation_pattern: authorship-bearing` (the curator ranged the candidates, not a confirmation of a pre-narrowed default). This is the creative act proper, and it reads as a first-class step distinct from generation and from governance.

- **Governance (the durable record).** `ASSET-MSG-HG-001-HERO-001`, `governed_output`, curator ASK, captured 2026-06-10, produced **entirely in-base with no external import** — a prototype-generated *output*, not an imported synthetic input. In this instance **selection and governance co-locate**: one carrier holds both the makes-true selection rationale and the governance record. The doctrine's selection-≠-governance distinction is still legible (the rationale names both acts explicitly) even though one field carries both — which is exactly the co-location the doctrine predicts for SKU/collection and, here, marketing.

The topology reads end to end from the re-expressed instance, as a function-order projection. A reader who has never seen the Airtable base can follow the brief opening an aperture, generation filling it, a human closing it, and artifact governance binding it (the governance record carries the trace).

## What survives extraction

The package's load-bearing distinctions carry tool-independently:

1. **The full chain** — intent → discretion → variance → selection → governance — is reconstructable from the instance alone.
2. **The grammar separation** — discretion (aperture grant) vs constraints (what may not vary) vs references (anchors) as three distinct carriers, not one fused field.
3. **Selection as a first-class act** distinct from both generation (mechanical) and governance (the record) — legible even where selection and governance co-locate in one carrier.
4. **Authorship-bearing vs confirmation-bearing curation** — the instance records which pattern produced the asset (`authorship-bearing`, full-candidate-space), and *where* authorship sat (upstream at prompt-remediation as well as at the seam).
5. **Mode shape** — products peripheral when the message is the anchor; the mode reads from the instance, not from a schema.
6. **Provenance richness** — curator, pattern, capture reason, rationale, timestamp, candidate-of-origin, and the in-base / no-external-import property all survive as instance content.
7. **Held / absent status as content** — the support slot (`planned`), the references (image-pending), and the prose required-output-set all re-express *with* their held status, rather than silently disappearing.

## What becomes an instantiation-plan requirement (conceptual — not entity design)

For a second substrate to hold and run this package, it must be able to — stated as capabilities, not tables/fields:

- **Represent** the information kinds as *optional* carriers — a package populates, inherits, or omits each as the workflow needs; nothing here is a mandatory-filled field.
- **Represent** an **accumulating candidate set** that is distinct from the single governed output — variance must be able to exist as a set before one element is elevated.
- **Preserve** a **substrate-neutral link from the selected candidate to the governed asset** — the worked substrate uses an attachment-id string (see below); any substrate must carry *some* stable candidate→asset reference that means something outside that tool.
- **Support** **selection and governance either co-located or separated** — one instance may carry both in one record (as here); another (campaign-mode) may separate upstream authorship from the seam record. The carrier shape must permit both.
- **Support in-place capture** — generation, accumulation, selection, and governed-capture must be expressible *without* an external import step, so the governed asset is a produced output, not a re-imported file.
- **Support generation-invocation settings separately from prompt text** — output framing / aspect ratio / resolution / model choice must be representable as invocation configuration rather than being buried in the prompt body.
- **Preserve held / absent / inherited status** — a planned slot, an image-pending reference, a brand-system constraint inherited by a packet must each be representable as such.

This is the portability-pressure depth the frontier authorizes. It deliberately stops short of naming entities, field types, or relationships — that would be schema / structured IA v3, both frozen by the current source-of-intent.

## What was Airtable-shaped (honest markers)

Where the worked substrate carried something the package needs but in a tool-specific way:

- **Candidate set as an attachment array.** The seven candidates live as `slot_generated_image_v1` (a `multipleAttachments` field) on the slot. "Attachment array on the slot" is an Airtable convenience; the package needs *an* accumulating-candidate carrier, not that specific shape.
- **Selection link as an attachment id.** `generated_assets.source_attachment_id = "attlMAX3ps9LV5DZl"` points at the chosen slot attachment. Outside Airtable, an attachment id has no meaning — a second substrate needs a content-hash / UUID / equivalent (the same distortion extraction-v1 flagged at the SKU slice).
- **Capture mechanic.** The governed asset was produced by Airtable's internal Path-B attachment-copy (slot candidate → `asset_attachment`). The *property* that matters (in-place capture, no external import) is portable; the copy mechanic is not.
- **Substrate scaffolding generally** — bidirectional link reciprocity, lookup auto-surfacing, single-select option objects, formula/rollup fields — all per extraction-v1's distortion list; not re-derived here.

These are quarantined in the YAML appendix's `substrate_worked_example` block, explicitly marked as *how this substrate holds the package*, not as package content.

## First-reader legibility check

Against the two front-door audiences:

- **Evaluator (creative-ops / visual-production systems owner).** Can read the package as a structured statement of intent / discretion / constraints / references / outputs / selection / governance, and see the one proven chain, without touching Airtable. The YAML's comments and held-status markers carry the "what's proven vs held" the evaluator needs.
- **Implementer.** Gets, from the instantiation-plan section, the *capabilities* a substrate must provide — enough to assess a candidate substrate, without a schema being prescribed.

What a first reader still cannot get here, stated honestly: a *reusable package grammar* (this is one instance, not a template), a second *real* substrate instantiation (this walks the plan, it does not build it), and the marketing mode beyond the single hero slot.

## Scope-bound caveats

- One package, one mode (marketing / message-driven), one slot (the hero). The support slot is held; the full marketing mode is not closed.
- The references are records-with-notes only (image-pending); visual anchoring in this instance was prose-carried. A future instance with real reference images would pressure the visual-anchor carrier differently.
- The YAML appendix is a concrete instance, not a schema and not a grammar. Field names in it are *this instance's* readable structure, not a required shape.
- The instantiation plan is conceptual (represent / preserve / support). It authors no entities, field types, or relationships.
- Single substrate read (Airtable `app4sBiFw2tft17VF`), single snapshot, read-only. No mutation occurred.

## Self-superseding clause

This v1 should be superseded by:

- a **second real substrate instantiation** of this package (YAML/JSON doc, a different tool, a data store) — which would convert the instantiation *plan* into instantiation *evidence*;
- a **different package** (SKU / collection / campaign) re-expressed the same way — which would pressure cross-mode portability of the package object;
- a **package grammar** attempt — once portability of concrete instances is established and a reusable template earns its place (explicitly *not* this artifact's job);
- an **operational consumer** that reads a package instance — which would convert portability pressure into operational pressure;
- a subsequent milestone that absorbs portability evidence into the architecture's claim discipline.

It does not supersede `non-airtable-extraction-attempt-v1.md` (the SKU/JSON-Schema leg), the 2c package map, the structured IA model v2, or any milestone. Those remain authoritative for their subject matter.

## YAML appendix — the 2c marketing-hero package instance

# Portable asset-definition package — one concrete instance.
# The proven 2c "Spring Refresh" marketing-hero chain, re-expressed tool-agnostically.
# This is an INSTANCE, not a schema and not a reusable package grammar.
# Information kinds are POSSIBLE carriers: a package populates, inherits, or omits each
# as the workflow needs. Held / absent / inherited / substrate-shaped items are flagged in comments.

package:
  id: PKT-MSG-HG-001                      # stable, substrate-independent identity
  mode: marketing / message-driven        # anchor is the offer/message, not a SKU
  brand_system: Warm Restraint            # synthetic prototype-aesthetic instance for this worked example
  status: draft                           # packet-level lifecycle (worked substrate value)

  business_intent: >
    "Spring Refresh" seasonal offer. Anchor is the message/offer, not a single product:
    communicate renewal and transparent value within Warm Restraint.

  creative_intent: >                      # the aim
    Message-bearing composition: room to carry an offer/headline; warm daylit refresh feeling;
    products serve the message rather than being the subject.

  creative_discretion:                    # the aperture grant — a carrier distinct from constraints and references
    latitude: >
      Which bath-textile pieces appear and how they are arranged; camera framing and crop;
      surface choice (light wood or soft stone); and the placement and extent of the
      copy-overlay negative space may vary.
    bounded_by: [BC-WR-PALETTE, BC-WR-LIGHTING, BC-WR-MATERIAL, BC-WR-NEGATIVE]
    anchored_to: [REF-WR-BRANDSYS-01, REF-WR-PALETTE-01]
    decision_owner: ASK (marketing curator-of-record)
    closes_at: hero-slot curation         # the aperture closes when one candidate is selected

  constraints:                            # what may NOT vary — distinct carriers, each typed by normative force
    - key: BC-WR-PALETTE
      force: presentation_rule
      scope: brand_context / Warm Restraint    # brand-system-layer; inherited by the packet
      text: >
        Palette: soft white, oat, cream, warm beige, light wood. Warm-neutral only;
        no saturated color, no high contrast.
    - key: BC-WR-LIGHTING
      force: fidelity_rule
      scope: brand_context / Warm Restraint
      text: >
        Bright daylit interior register (~4500-5500K), abundant soft natural daylight,
        soft diffuse shadows, airy/high-key. No moody/low-key, no dramatic studio strobe.
    - key: BC-WR-MATERIAL
      force: fidelity_rule
      scope: brand_context / Warm Restraint
      text: >
        Material honesty: natural-fiber textiles (linen, cotton, waffle, terry), light oak/ash,
        matte/low-gloss glazed ceramic. Clean, refined, uniform; visible weave/grain rendered cleanly.
    - key: BC-WR-NEGATIVE
      force: hard_requirement              # avoid-list / negative reference function
      scope: brand_context / Warm Restraint
      text: >
        Avoid: metallic accents (chrome/brass), moody/low-key/chiaroscuro, rustic/artisanal/
        weathered/distressed, styled clutter, decorative trims/contrast hems, walnut/rich-oak,
        glossy glam-luxury, hotel-spa vignettes.

  references:                             # visual anchors — distinct carriers
    - key: REF-WR-BRANDSYS-01
      role: approved_directional_reference
      scope: brand-system master; shared across all four mode packets   # inherited, not packet-local
      note: >
        Warm Restraint brand-system master visual anchor — clean warm restraint; bright daylit;
        warm-neutral palette; natural-fiber materials; generous negative space.
      image: null                          # HONEST MARKER: records-with-notes only; imagery pending in this instance — no bytes attached
    - key: REF-WR-PALETTE-01
      role: supporting_input
      note: "Warm-neutral palette board: soft white / oat / cream / warm beige / light wood. Supports BC-WR-PALETTE."
      image: null                          # HONEST MARKER: image-pending; prose slot_prompt carried the anchoring here

  products:                                # PERIPHERAL in marketing mode — present but subordinate to the message
    - SKU-HG-TOWEL-001
    - SKU-HG-BATHMAT-001

  required_output_set: >                   # the obligation — prose in this instance; mode-specific structured shape (messages) HELD
    1 message-hero (offer-ready, copy space); 1 secondary message-support.

  output_slots:
    - key: SLOT-MSG-HG-001-HERO
      role: message_hero
      sort_order: 1
      expected: "Spring Refresh offer-ready hero with clean negative space for headline/offer overlay."
      status: accepted                     # the obligation is met by the governed asset below
      slot_prompt: >                       # composition + aesthetic ONLY; output framing (3:4 portrait) is a separate setting, not prompt text
        A single photograph — not a grid, collage, contact sheet, triptych, or multi-image layout.
        Photographic marketing hero image for a "Spring Refresh" everyday-quality home-goods promotion,
        in a clean warm-restraint register. A bright, airy, sunlit interior — abundant soft natural
        daylight around 4500–5500K, soft diffuse shadows, high-key and open. Warm-neutral palette only:
        soft white, oat, cream, warm beige, light wood (finely-grained oak or ash, not walnut, not
        weathered). A small, considered arrangement of everyday bath textiles — a neatly folded linen
        waffle bath towel in unbleached oat, a cotton waffle bath mat in warm cream, and a soft white
        cotton terry robe folded or softly draped with the towels (not hung) — arranged on a low
        light-wood ledge, shelf, or built-in bench set parallel to a plain, softly-lit wall. All
        natural-fiber with clean visible weave and terry texture, matte, refined and uniform (not raw,

      sort_order: 2
      expected: "Secondary message-support frame reinforcing the offer."
      status: planned                      # HELD — deliberately not generated; the proof terminated at the single hero

    status: governed_output

      The capture note carries BOTH the makes-true selection rationale AND the governance record.
    provenance:
      from_candidate: the selected post-remediation candidate
      # substrate-shaped: the live link is an Airtable attachment id ("attlMAX3ps9LV5DZl"), meaningless off-Airtable.
      # a second substrate needs a substrate-neutral candidate->asset link (content hash / uuid).
      capture_reason: "cross-candidate selection from 7 in-base takes (post prompt-remediation); most-true-to-intent"
