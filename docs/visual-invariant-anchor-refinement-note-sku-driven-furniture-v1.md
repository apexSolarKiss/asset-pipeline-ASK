## Why This Exists

PR #119 recorded Partial success for the pre-composed shared invariant prompt probe.

Text-composed shared invariants materially improved set coherence.

Residual drift remained, especially at the HERO background / studio-plane level.

That result refines the repo's understanding of what visual invariant anchoring may need to mean.

## Evidence Basis

The PR #119 findings note recorded that:

- slot roles held
- set coherence improved materially
- HERO remained slightly misaligned at the background / studio-plane level
- higher-layer invariant representation is more strongly earned
- no structure was chosen

## Core Refinement

Product-truth anchor and visual invariant anchor are not the same job.

Background is too narrow a term for the remaining pressure.

The emerging pressure is for a shared visual-system or family / world anchor.

This anchor may need to carry:

- background / studio world
- lighting behavior
- shadow behavior
- camera language
- overall family tone

## Option D Split

### D1 // External Visual Reference Anchor

D1 uses manually sourced or uploaded reference imagery.

The reference imagery is used as visual guidance input.

This remains an input / reference pattern.

### D2 // Generated Visual Invariant Anchor

D2 uses a generated upstream artifact that establishes the shared visual system.

That artifact is then fed downstream into slot generation alongside:

- product-truth image
- textual invariants
- slot-specific variation instructions

D2 introduces a multi-step pipeline rather than only a single-step slot-generation pattern.

## Why D2 Is Structurally Distinct

D2 is not just another reference.

It is a governed upstream artifact candidate.

It may require its own role in the pipeline.

It suggests a dependency shape:

- upstream invariant generation
- downstream slot generation

It potentially sharpens existing pressure around generation steps / attempt tracking, but it does not yet decide that structure.

## Open Questions

- Should a visual invariant anchor remain an external reference or become a generated upstream artifact?
- If generated, should it be treated as a packet-level artifact?
- Can Airtable AI field-agent generation consume a second image input in addition to the existing product-truth image?
- Is `reference_assets` a sufficient temporary home, or would a different representation eventually be needed?
- How should a visual invariant anchor relate to `generated_assets` capture boundaries if it is generated but not itself a slot output?
