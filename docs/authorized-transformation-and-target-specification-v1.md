# Authorized Transformation and Target Specification (v1)

## Posture

```text
bounded architecture pressure / model attempt
not schema · not structured IA model v3 · not validator / runtime · not VPA v3
does not revise product truth in place
does not create a new workflow mode
does not authorize any client or prototype work
one model attempt against concrete cases, not an options matrix
self-superseding when operational pressure or a later VPA version absorbs it
```

## What this is

A bounded pressure note on one architectural seam: **how a decision-authorized delta from a baseline authority becomes a new target specification, while the unchanged facets remain governed by that baseline.**

Product truth remains authoritative and invariant within the declared product, variant, or physical state — that is not in question here, and nothing in this note narrows it to physically existing objects. An approved specification, a measured drawing, or a declared variant is already product truth. What the architecture does not yet explicitly model is the **authorization seam**: how an authorized facet delta produces a new target the run is measured against, and which source retains authority over which facet across that delta. The worked cases have not operationally pressured that seam.

This note names the model, tests it against four cases, and marks what is earned versus held. It authors no carrier.

## Vocabulary guard

Four things are routinely collapsed into "what the image is about." They are distinct, and the collapse is what makes the seam hard to see:

```text
production anchor           what organizes the commercial ask
                            (SKU · collection · message/offer · campaign concept)

commercial referent         the thing being sold

depicted entity / element   what may appear in frame — including elements that are
                            not entity records (a spatial region, a composite
                            arrangement, a copy-bearing field)

slot-assigned depiction      what the slot says a depicted element is doing
role                         in this image
```

Worked instance — the marketing / message-driven package `PKT-MSG-HG-001`:

```text
production anchor      the seasonal offer / message
commercial referents   the two linked products
depicted elements      the textile arrangement · the room · the copy-safe region
assigned roles         arrangement = principal visual content
                       products = subordinate constituents
                       room = environment
                       copy-safe region = message-bearing obligation
```

The package states this today in prose — `creative_intent` says the products *"serve the message rather than being the subject,"* and the copy-safe region appears across the slot's `expected`, the aperture latitude, and the slot prompt without ever being an entity. **No structural carrier is implied for any of the four by this note.** The guard exists so the vocabulary does not fuse while the question is open.

## The model

```text
        target definition carried directly from source of intent
                                 |
              — and / or, when the target differs from a baseline —
                                 |
baseline truth claims                      authorized transformation
  entity / facet / source /                  preserved facets
  variant or state                           changed facets
                                             authorized decision path
                     \                      /
                      >>  target specification  <<
                                 |
                       candidate depiction
                                 |
                      conformance observation
                                 |
                            selection
                                 |
                       artifact governance
                                 |
               governed asset  +  governance record
                                 |
               optional later physical validation
```

**The baseline / transformation branch is conditional.** A target specification may be authored directly from source of intent where no baseline transformation is at issue — case 1 below is exactly that. This note models the additional authorization seam required **when a target differs from a baseline**; it does not claim every target specification requires a baseline or a transformation, and it does not recast every prospective package as a transformation package.

**Baseline truth** may be a physical observation, an approved specification, a CAD or measured drawing, an existing product variant, or another authority-bearing source. It carries facets, and it carries the variant or state it describes.

**Authorized transformation** names which facets are preserved, which are changed, and the decision path under which the change is bound. The decision owner owns the granted aperture, its closure, answerability, and recourse; an authorized decision-maker binds the target within delegated scope. The roles may coincide, but the architecture does not presume they do.

**Target specification** is the resolved prospective definition the run is measured against. It is what conformance observes; it is not itself an observation. **A new target becomes operative only when bound through an authorized decision path.**

The tail keeps four acts distinct:

```text
conformance          observes a candidate against the target specification
selection            adjudicates among candidates and closes the aperture
                     under a recorded decision basis
artifact governance  binds the accepted result to its claim, permitted use,
                     circulation, approval, and answerability
governance record    carries the durable trace and the stated basis
```

### Required distinctions

| | kind | |
|---|---|---|
| baseline truth | descriptive / evidentiary | what is so, of a declared variant or state |
| authorized transformation | directive, bound through the authorized decision path | what may differ, and under what authority |
| target specification | prospective normative definition | what the run is for |
| candidate depiction | realized state | what generation produced |
| conformance | observation against the target | not the selection judgment |
| selection | adjudicative judgment | chooses one candidate, closes the aperture, and records the decision basis |
| governed asset | accepted artifact | the selected depiction bound to its claim, permitted use, circulation, approval, and answerability |
| governance record | durable trace + stated basis | records the selection basis, authority, provenance, permissions, acceptance, and any authorized exception |

## What this does not claim

**Product truth is not made context-dependent.** It remains invariant within the declared product, variant, or physical state. An authorized transformation does not relativize truth to context — it authors a *new target definition* whose changed facets are explicitly authorized and whose preserved facets remain governed by the baseline. The existing principle stands unchanged:

```text
context does not rewrite product truth
a new target becomes operative only through an authorized decision path
```

This is a qualification of source authority, not a reversal of the normative-source architecture. `docs/visual-payload-architecture-v2.md` remains authoritative for the convergence picture; facet-scoped fidelity — truth projecting selectively into a slot's obligations — already exists there and is not invented here. The narrow addition is that **source authority may be qualified by the variant or state the source describes.**

## Relation to the tested resolution calculus

A requested change that lacks sufficient authority does not become creative discretion because a model can render it. In the slot-resolution calculus pressured at A1 depth, that condition resolves to **`authorization-required`** — one of five terminal states, alongside `resolved`, `judgment-required`, `input-required`, and `unsatisfiable`. That test explicitly did **not** adopt its vocabulary as canonical architecture terms; the alignment is cited as corroboration of the shape, not as canon.

## Cases

**1 // marketing / message-driven hero — no baseline, no transformation.**
In the worked package store, both references are `image: null · byte_status: not_held · status: image-pending`. The store nonetheless carries the target definition, seven candidate **records**, and a governance **record**. The underlying run produced image candidates and a governed asset; this store deliberately carries **no image bytes** — it preserves candidate identities, the selected-candidate link, and lifecycle state without their payloads. So the store holds the governance record while the governed asset's bytes live elsewhere, which is exactly the distinction the table above draws.

The target here was authored directly from source of intent: there is no baseline authority and no authorized transformation. That establishes both that a physical baseline is *optional* and that **the baseline / transformation branch is conditional** — the model must not be built as a mandatory linear progression.

**2 // unreleased variant (colorway).**
An existing variant is the baseline; the target is an unreleased colorway.

```text
preserve   geometry · proportion · joinery · weave · scale
change     colorway   ← the authorized delta
```

Roles are trivially coincident here — one product, principal subject, no people, no part–whole. **The transformation structure is therefore necessary independently of any role question.** This is a baseline-to-target relation between two product definitions; it should not be forced into a temporal reading.

**3 // pre-completion property visualization (generalized).**
A space is photographed in an early, incomplete condition; the image must depict an authorized future configuration.

```text
baseline    the early-condition photograph — governs geometry, apertures,
            proportions, condition, at the state it records
authorized  approved design and furnishing intent
target      the authorized future configuration
later       an eventual physical state, optionally compared
```

Here the baseline is genuinely temporal, and its authority is **partial**: it governs geometry and does not govern finishes or furnishing. Same preserve/change shape as case 2, arrived at from a different direction.

**4 // ordinary detail slot — role and part–whole already recoverable.**
In `PKT-SKU-009`, an ordinary product packet runs hero, profile, and detail obligations. The detail slot's principal subject is a *part* of the commercial referent. The live carriers are:

```text
expected_output_role         singleLineText — "Role-level identity before generation;
                             flexible because SKU-mode roles are not global enum doctrine"
expected_output_description  multilineText — the expected output burden
slot_prompt                  multilineText — prototype probe; not final schema doctrine
```

Role identity is **free text by design**, consistent with the same base's treatment of `asset_role`, `capture_reason`, `curation_pattern`, and `curator` — all held as text with an explicit rationale of deferring premature enum doctrine. Together these carriers make ordinary depiction-role and part–whole assignment recoverable without a structural relation. **No general role carrier is earned by ordinary product work.**

## Earned and held

**Earned as a strongly supported architecture candidate:** the baseline-truth + authorized-transformation → target-specification model, as a *conditional* branch into target specification. It is necessary in case 2 with roles doing no work, recurs in case 3 from a different direction, and is compatible with case 1, where the branch is simply absent. It is not specific to any one domain or product kind.

**Not claimed:** canonical VPA revision · operational proof · a new product-truth carrier · a new workflow mode · any schema requirement.

**Held.**

```text
explicit slot → depicted-element → role relation
   trigger: a real package or a structured consumer cannot reliably reconstruct
   the assignment from current slot carriers without operator context
   risk indicators (not triggers on their own): the depicted subject differs from
   the commercial referent · a part must be individuated inside a complex whole ·
   multiple roles coincide on one element

depicted-entity relations — wears · uses · holds · part_of · occupies
   surfaced by garment-on-body realization and by part-of-space depiction;
   existing use-state / action vocabulary and prose may already suffice — untested

later physical / as-built comparison
   verification of a governed asset against subsequent physical reality;
   distinct from the governed-output-continuity reference function, which covers
   re-entry as a reference rather than verification against reality

explicit rights and permitted-use carriers inside governance
   release · territory · duration · exclusivity · synthetic-alteration permission ·
   likeness · reference licensing · publication. Artifact governance already binds an
   accepted result to its claim, use, and answerability, and the governance record
   carries the trace; these are an under-developed part of that binding, not a family
   outside it
```

## What this note does not do

- Authors no schema, field, entity, validator, runtime, structured IA model v3, or VPA v3.
- Revises no existing artifact in place; `visual-payload-architecture-v2.md` and the doctrine note remain authoritative for their subjects.
- Creates no workflow mode. A property or project is a commercial referent and an operational container respectively; neither establishes a mode-specific layer on this evidence.
- Adopts no role vocabulary and proposes no enum.
- Presumes no identity between the decision owner and an authorized decision-maker.
- Does not claim every target specification requires a baseline or an authorized transformation.
- Does not collapse the governed asset into the governance record, or either into the act of governing.
- Authorizes no prototype run, package build, Airtable mutation, or client engagement.

## Self-superseding clause

This note should be superseded by: a real package that carries an authorized transformation operationally; a structured consumer that must resolve baseline-versus-target authority; a later VPA version that absorbs facet-and-state-scoped source authority; or a milestone that folds the distinction into the architecture's claim discipline.
