## Context

The Gate 2 image-bearing reference path has landed as Supported for `PKT-SKU-009`.

That gives the visual-reference binding question a bounded SKU-driven Furniture v1 answer: for this prototype chain, an image-bearing attachment lookup behaved as a stronger visual input than the surfaced URL-reference path.

Raw generated images can exist on `output_slots.slot_generated_image_v1`.

Existing structural decisions already distinguish:

- `output_slots` as first-class expected output obligations
- `slot_generated_image_v1` as raw slot-level generated output
- `generated_assets` as promoted / captured asset records for review, governance, evidence preservation, release-readiness, or delivery
- `slot_status` as a single flat lifecycle field for the expected output obligation

The unresolved pressure is how raw slot outputs become durable governed assets without corrupting evidence history.

## Candidate Next Paths

## Decision

Decision:

- Option 1: capture / governance mechanics becomes the next primary repo chain.

This choice builds on the existing B-evidence generated-assets promotion boundary.

It does not reopen that boundary.

Under that boundary, `generated_assets` are created only after an explicit review / capture action, not automatically for every raw slot-level generated image.

This choice also builds on the existing single flat `slot_status` lifecycle.

It does not reopen the lifecycle decision.

The next active question is not whether the B-evidence rule or the flat `slot_status` lifecycle should exist. The next active question is how the raw-slot-to-governed-asset bridge should be represented and controlled without retroactively mutating evidence.
