## What Milestone 16 Marks

The plateau identity is a single load-bearing claim:

**A materially different relational target has now been exercised for one package. Its tested semantics were preserved and recoverable, but this does not establish a repeatable package consumer or consuming grammar.**

Milestone 15's next-evidence condition named a materially different second target before any consuming-grammar talk, and its accepted consumer evidence was limited to one known-achievable filesystem target. PostgreSQL materially advances that plateau because it is **not another filesystem representation**: it is a typed, relational, constraint-bearing target whose affordances pressure exactly the source-depth and authorization distinctions the architecture was trying to preserve.

## The split, stated precisely

```text
TARGET DIVERSITY LEG
  SATISFIED at constructive-instantiation depth

CONSUMER REPETITION LEG
  NOT TESTED

CONSUMING GRAMMAR
  NOT EARNED
```

The distinction is not a technicality. The constructive run was **not** a repetition of the formally calibrated package-instantiation planning consumer on target two. It was an executor-authored prototype representation built from the architecture attempt and a design checklist, followed by one instruction-isolated assisted-recovery pass. Target diversity was exercised; consumer repetition was not attempted; therefore no step toward a consuming grammar was taken.

## Earned

```text
one frozen package concretely instantiated in PostgreSQL 17.11
tested source semantics preserved and recoverable at constructive-instantiation depth
no target incompatibility established
the nine durable findings recorded in the evidence boundary
```

The evidence boundary artifact carries the exact claim, the supporting run facts, and the recovery-pass context limitations: [`docs/postgresql-constructive-instantiation-and-recovery-evidence-boundary-v1.md`](../postgresql-constructive-instantiation-and-recovery-evidence-boundary-v1.md).

The most architecturally useful finding is that the representation carried package→slot **containment** and the AP lifecycle classification, but **not the inheritance rule** that explains why slot-level narrowing of a packet-level aperture is lawful. Lifecycle position and inheritance layer are orthogonal axes; a slot prompt narrowing a packet grant is role-specific narrowing within the scope hierarchy, not a peer carrier conflict. The gap is representation legibility, not package contradiction.

## Phase 3 frontier disposition

Milestone 14 separated the portability frontier into recovery, auditability, and consumability. This marker dispositions the portability / consumability lanes that were held after milestone 15:

```text
specific held PostgreSQL lane
  DISCHARGED — it is no longer unrun

bounded second-target representability / recoverability
  EARNED for one package at constructive-instantiation depth

formal blind-test controller apparatus
  CLOSED — no reader run occurred;
  the attempted controller lineage was not viable

repeatable package-instantiation consumer
  STILL HELD

consuming grammar
  STILL HELD

general portability
  STILL HELD
```

The answer is neither "the hold remains untouched" nor "the condition is satisfied." The **target** question was answered. The **consumer-generalization** question was not.

The original PostgreSQL lane was a prepared but unrun relational lane. The constructive unit superseded that practical state without retroactively validating the formal blind-test controller apparatus attempted before it. **No reader run occurred under that apparatus** — it was abandoned during construction, so its closure records an unworkable instrument, not a negative consumer-test result. That lineage is closed and is not revived by this marker.

## Next-evidence condition

No further PostgreSQL run opens by default. The evidence has reached a clean plateau. Another target, or another consumer run, now requires a **newly stated uncertainty** — not proof-chain momentum. A consuming grammar remains earned only by consumer repetition, which this run did not attempt.

## Self-superseding clause

Milestone 16 is a plateau marker. It should be superseded by a subsequent milestone when the next architectural plateau is reached; by a consumer-repetition run on a materially different target, which is the move that would bear on a consuming grammar; or by a subsequent result that revises the evidence boundary this marker absorbs.

It does not supersede milestone 15 or the package-instantiation consumer evidence boundary, which remain accurate at their own evidence depth; nor milestone 14's portability-frontier separation, which remains the governing architecture posture; nor the portability legs, the apex definition-layer artifact, or milestones 7–13.
